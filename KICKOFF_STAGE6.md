# Stage 6 — the Eulerian density: tests of the diagnosis, then the Eulerian metric (paste into the local Claude Code session)

---

Read `notes/eulerian_power.pdf` first (Chinese; 9 pages, §5.7 is about your J-loss). It is the answer to the observation in `runs/REPORT_6.md` §4b that no model has `P_delta/P_true = 1`. Summary of what it derives, so you know what each experiment below is testing:

* In the octave band, `d_model = a d_true + n` with `a = r sqrt(P/P_true)` and per-component noise variance `sigma_n^2 = (P/P_true - r^2) Var(d)` (eq. 4). Independent noise damps the Eulerian density power by exactly `exp(-k^2 sigma_n^2)` (eq. 6; verified on a 53%-multi-stream Zel'dovich field, `checks/smear_check.py`, to 10% up to `k_Ny,c`, and the noise spectrum does not matter). Shrinking the detail by `a < 1` compacts every multi-stream patch, so the 1-halo term rises as `|u(ak)|^2/|u(k)|^2` (§3.4). Noise adds Lagrangian power and removes Eulerian power; shrinkage does the opposite — that is the whole inversion.
* Exact limit: the generative flow has `P_delta/P_true = 1` by the flow-matching theorem; an emulator-mode *conditional sampler* has it in expectation even with `r < 1`; a *conditional mean* (the regression) never has it in multi-stream regions (§4). So the regression's excess is intrinsic and the flow's deficit is a learning residual that the Lagrangian L2 loss cannot see.
* Fix: any positive-definite quadratic form that depends on `(x_t, C, t)` but not on `x_1` leaves the flow-matching minimiser unchanged (§5.1). Use the *Eulerian linearised metric* `Q_E(e) = mean |h_e|^2`, `h_e` = first-order CIC density change under the error `e` deposited at the coarse field's Eulerian positions (§5.2, `eulerian_metric.py`). Its kernel is exactly the density-invisible errors (relabelling of coincident particles, solenoidal momentum), so a finite network pushes its residual there and `P_delta` can reach 1 without `r -> 1`. Plus the coarse Eulerian density pulled back to `q` as an input channel (§5.4). A nonlinear CIC loss on the x-prediction biases the velocity by `lambda (1-t) E[J^T (rho(x1_hat) - rho(x1)) | x_t]` (§5.5) — allowed for the regression (it is the Paper-IV loss), not for the flow.

Your J-loss proposal is analysed in §5.7 of the note: the *diagnostic* is right (noise broadens the `J = det(I + dPsi/dq)` distribution, shrinkage narrows it by `a^3` — both measured); the *admissible* loss form is the linearised quadratic form `Q_J(e) = <|tr[adj(A) de/dq]|^2 / (J^2 + eps^2)^{p/2}>` with `A, J` from the state (Jacobi's formula; `dJ/J = div_x e`, the Lagrangian-frame density change), implemented as `jacobian_form`; a nonlinear `log|J|`/quantile match on the flow's x-prediction has exactly the same bias as the CIC loss on the x-prediction (§5.5) and is for the regression only. `Q_J` has no relabelling kernel (it constrains stream by stream), so it is expected to match `Q_E` in single-stream regions and to fall short in multi-stream ones — that is the comparison to run. CIC *is* differentiable almost everywhere (piecewise linear in the positions); the "index not differentiable" worry is unfounded.

`eulerian_metric.py` (new, root directory) has `cic_deposit`, `cic_gradient_deposit`, `pullback`, `eulerian_positions`, `eulerian_form`, `eulerian_inputs`, `jacobian_form` (+ `spectral_gradient`, `jacobian_and_adjugate`) and a self-test (`python eulerian_metric.py`: mass conservation 0, first-order identity 1e-2, kernel test 0.25/0.041/0.016 for pairs closer than 0.5/0.2/0.1 cell, Jacobi identity 1e-4). Run it first on the Mac (CPU) and record the numbers in the RUNLOG. Do not modify it except to fix an MPS incompatibility, and say so if you do.

Append everything to `runs/RUNLOG.md`; finish with `runs/REPORT_7.md`.

**B. Code (small, additive; `octave_flow_toy.py` only, plus `results.json` fields).**

1. `--loss-metric {lag,qe,qj}` (default `lag`; `qe`/`qj` are the *quadratic forms* — distinct from the existing `--cic-weight`/`--jac-weight`, which are the nonlinear losses on the x-prediction and stay as they are), `--lambda-e FLOAT`, `--euler-positions {coarse,interp}` (default `coarse`), `--jac-p FLOAT` (default 2), `--jac-eps FLOAT` (default 0.1). With `qe`: `e = v_theta - (x1 - x0)`; `pos = eulerian_positions(Pc_over_h, offset)` for `coarse` (the prolonged coarse field already in units of `h_f` in `Batcher.make`), or `eulerian_positions(x_t.detach(), offset)` for `interp`; `loss = mse(e) + lambda_e * eulerian_form(e, pos)` (no k-weight). With `qj`: `loss = mse(e) + lambda_e * jacobian_form(e, Pc_over_h or x_t.detach(), p, eps, fft_device)` — the state field plays the role of `pos`. At step 1 print both terms; the default `lambda_e` should make them equal at step 1 (record the value, separately for `qe` and `qj`). The forms run wherever the network runs; if `scatter_add` fails on MPS, compute the Eulerian form on the CPU and say so; the Jacobian form needs the FFT, so it uses `--fft-device` like the other spectral ops.
2. `--eulerian-inputs`: append `eulerian_inputs(Pc_over_h, offset)` (1 channel, `log(1 + delta_c)` at the coarse Eulerian position of `q`) to the network input; `cin += 1`; apply the same cubic-group augmentation as the other scalar channels (it is a scalar field, so it only needs the spatial transform). Store the flag in the checkpoint so `--eval-only` rebuilds the right `cin`.

Evaluation (`summarize`): add Eulerian metrics for every line — `P_delta/P_true` at `k_Ny,c` and `1.5 k_Ny,c`, `r_delta` at `k_Ny,c`, the mass fraction at `delta > 100`, the T3 kernel fraction (both `Q_E` and `Q_J` versions), and the `J = det(I + dPsi/dq)` quantiles (1/5/25/50/75/95/99 %) of prediction and truth plus the fraction `J < 0` — computed on the CPU with `eulerian_metric`.
